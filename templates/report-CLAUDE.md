# 사람다운 글쓰기 규칙

<!-- 비서 견본: bin/setup 이 ~/report/CLAUDE.md 로 복사한다. 아래 0-1 의 <학번>·<이름> 을 내 것으로 바꾼다. -->

이 폴더에서 보고서, 과제, 설명글 등 한국어 문서를 쓰거나 고칠 때 따른다.

아래 규칙은 실제 사람들이 "AI가 쓴 티가 난다"고 지적한 패턴을 모은 것이다. 출처는 영어 위키백과 편집자 가이드, LessWrong·Hacker News 토론, 나무위키, 대학생 커뮤니티 글, 국내 교정 도구 개발자 인터뷰 등이며 목록은 맨 아래에 있다.

## 0-1. 파일명과 이름 표기

제출용 문서는 파일명을 `학번_이름_과목_문서종류_번호` 형식으로 짓는다. 학번은 <학번>, 이름은 <이름>다.

- 예: `<학번>_<이름>_생화학_예비보고서_1.md`, `<학번>_<이름>_생화학_결과보고서_2.md`
- 파일은 과목 폴더 `~/report/<과목>/` 안에 둔다 (파일명의 과목 부분과 같은 이름, 예: `유기약화학/`). 그림·참고 자료도 그 과목 폴더 안에 둔다.

문서 안에서는 제목(과 부제) 바로 아래에 학번과 이름을 오른쪽 정렬로 넣는다. Markdown에서는 아래와 같이 쓴다.

```markdown
# 제목
## 부제

<div align="right"><학번> <이름></div>
```

HTML로 쓸 때는 `text-align: right`로 같은 자리에 넣는다.

## 0. 기본 원칙

1. **겉으로 드러난 신호보다 원인을 고친다.** 위키백과 편집자들은 AI 글이 "평균으로 회귀"한다고 설명한다. 구체적이고 특이한 사실이 일반적이고 긍정적인 말로 바뀐다는 뜻이다. 예를 들어 "최초의 열차 연결 장치를 발명한 사람"이 "산업계의 혁신적 거인"이 된다. 금지어를 지우는 것으로 끝내지 말고, 그 자리에 구체적인 내용을 넣는다.
2. **하나의 표현보다 밀도를 본다.** 아래 패턴 중 하나가 한 번 나온다고 문제가 되지는 않는다. 여러 패턴이 한 문단에 몰리면 티가 난다. LessWrong 글쓴이의 말로는 "한 번은 정당한 수사지만 한 글에 다섯 번은 아니다".
3. **사실은 건드리지 않는다.** 문체를 다듬을 때 수치, 주어, 조건, 고유명사, 인용, 단위는 그대로 둔다. 고친 뒤에는 원문과 대조해 내용이 바뀌지 않았는지 확인한다.
4. **글쓴이의 생각이 보여야 한다.** 교수가 AI 과제를 알아채는 기준은 문장 하나가 아니다. "학생 수준을 벗어난 글", "어디에나 붙일 수 있는 결론", "내 생각이 안 보이는 글"이다.

## 1. 구체적으로 쓴다

- 일반론 대신 이 글에서만 할 수 있는 말을 쓴다.
  - ✗ "디지털 기술은 생산성을 향상시키며 중요한 역할을 한다."
  - ✓ 실제 사례, 수치, 관찰 결과, 수업에서 다룬 개념을 쓴다.
- 과장은 측정값이나 실제 동작으로 바꾼다.
  - ✗ "비약적인 성능 개선" → ✓ "응답 시간이 1.2초에서 0.4초로 줄었다"
  - ✗ "단 3초 만에 완성" → ✓ "측정 조건에서 3초가 걸렸다"
- 측정하지 않은 값, 확인하지 않은 사실, 찾을 수 없는 참고문헌은 쓰지 않는다. 모르면 모른다고 쓴다.
- 좋은 예와 나쁜 예(게임 리뷰):
  - AI: "변덕스러운 유쾌함으로 감싼 즐거운 열병의 꿈"
  - 사람: "울타리 너머로 소시지를 밀어 넣는 캐릭터가 좀 섬뜩하다"
  - 사람 쪽이 덜 모호하고, 게임이 실제로 어떤지 알려 준다.

## 2. 피할 문장 구조

| 패턴 | 예 | 고치는 법 |
|---|---|---|
| 대조 짝 문장 | "단순한 A가 아니라 B다", "A를 넘어 B다", "A라기보다 B다", "A가 아닌 B로서" | 대부분 "A가 아니라" 부분을 빼도 의미가 같다. B만 쓴다. 허수아비 A를 세우지 않는다. |
| 셋씩 맞춘 나열 | "효율성, 정확성, 그리고 신뢰성", 첫째·둘째·셋째 | 실제 항목 수대로 쓴다. 두 개면 두 개, 하나면 하나. |
| 예고 문장 | "지금부터 살펴보겠습니다", "여기서 흥미로운 점은", "핵심은 이것이다:" | 지우고 바로 본론을 쓴다. |
| 반복 요약 | "결론적으로", "종합하면", "즉", "다시 말해", "궁극적으로" + 앞 내용 반복 | 새 내용이 없으면 문단째 지운다. |
| 꼬리 해석 | "~하였으며, 이는 ~의 중요성을 보여준다/시사한다" | 근거 없는 해석은 지운다. 해석이 필요하면 근거와 함께 따로 쓴다. |
| 수사 의문문 | "~라면 어떨까요?", "그렇다면 ~이란 무엇일까?" | 평서문으로 쓴다. |
| "~하는 순간" 공식 | "포기하는 순간, 모든 것이 무너진다" | "포기하면 ~할 수 있다" |
| 결론 뒤집기 | "결론부터 말하면 A. 하지만 더 좋은 것은 B. 저라면 C." | 결론은 하나만 낸다. |
| 짧은 펀치라인 연속 | "코드는 그대로였다. 바뀐 건 모델이었다." | 연달아 쓰지 않는다. 보통 문장 안에 녹인다. |
| 과제·전망 공식 | "여러 한계에도 불구하고 ~는 앞으로 ~할 것으로 기대된다" | 실제 한계와 그 이유만 쓴다. |

문장과 문단 길이가 모두 비슷하면 기계적으로 읽힌다. 길이는 내용에 맞춰 자연스럽게 달라져야 한다.

## 3. 번역투 고치기

| 번역투 | 자연스러운 한국어 |
|---|---|
| ~을 통해 ~할 수 있다 | ~으로 ~할 수 있다 |
| ~에 의해 결정된다 | (행위자)가 ~을 정한다 |
| 보여집니다, 읽혀집니다 (이중 피동) | 나온다, 보인다 |
| ~에 대한 분석이 먼저다 | ~을 먼저 분석한다 |
| ~에 있어서 | ~할 때, ~에서 |
| ~에도 불구하고 | ~는데도 |
| 가장 흔한 실수 중 하나 | 흔한 실수 |
| ~로서 기능한다, ~의 역할을 한다 | ~이다, ~한다 |
| 이는 / 이러한 (매 문장) | 이것은, 이런, 또는 주어를 다시 쓴다. 남발하지 않는다. |
| 중요한 역할을 한다 | 무엇을 하는지 동사로 쓴다 (예: "인산기를 붙인다") |
| ~하는 것을 돕는다 | ~하기 쉬워진다 |
| 통찰, 인사이트 | 알게 된 점, 발견 |
| 강해진다/약해진다 (strengthen/weaken 직역) | 커진다/줄어든다, 취약해진다 |

위키백과 편집자들은 사람이 AI보다 더 많이 쓰는 표현도 정리했다. 쉬운 동사(썼다, 옮겼다, 사용했다), 단순 서술(~이다, ~가 있다), 단정 표현(유일한, 최초의, 가장)이다. 이런 표현은 그대로 쓴다.

## 4. 어휘

자주 지적되는 상투어다. 쓰더라도 한 글에 여러 번 쓰지 않는다.

- 한국어: 중요하다, 필요하다, 시사한다, 시사하는 바가 크다, 강조된다, 다각도로, 효과적으로, 다양한, 지속가능한, 혁신적인, 전략적 접근, 구조적, 실무적, 심층적으로, 궁극적으로, 비로소, 꽤 흥미롭다, ~로 보는 게 맞다
- 영어(영어로 쓸 때): delve, tapestry, testament, pivotal, crucial, underscore, showcase, foster, landscape, intricate, meticulous, vibrant, robust, navigate, elevate, journey, "serves as"
- 과장 은유: 마법 같은, 혁명적인, 판도를 바꾸는, 새로운 지평
- 개인 경험을 "우리는"으로 일반화하지 않는다. 내가 한 일은 "나는/제가" 또는 주어 생략으로 쓴다.

## 5. 어조

- **아첨하지 않는다.** "핵심을 찌르셨네요", "좋은 질문입니다", "완전히 맞습니다" 같은 말을 쓰지 않는다.
- **완곡 표현을 쌓지 않는다.** "~할 것으로 보인다", "~일 수 있다", "다만", "상당히 ~에 가깝다"를 습관처럼 붙이지 않는다. 확실하면 단정하고, 불확실하면 무엇이 왜 불확실한지 쓴다.
- **대화형 흔적을 남기지 않는다.** "알겠습니다", "도움이 되셨길 바랍니다", "원하시면 ~해 드릴까요?", "아래는 ~입니다" 같은 말은 문서 본문에 넣지 않는다.
- **문체를 섞지 않는다.** 보고서는 "~하였다" 해라체로 통일한다. "~함/~됨" 음슴체나 "~요" 체를 중간에 섞지 않는다.
- **맥락보다 지나치게 매끄럽게 쓰지 않는다.** HN 댓글: AI 글의 핵심 신호는 "그 자리에 비해 너무 잘 쓴 글"이다. 학부 보고서는 학부생이 쓴 것처럼 읽혀야 한다.

## 6. 서식

- 굵은 글씨는 정말 필요한 곳에만 쓴다. 문단마다 볼드를 넣지 않는다.
- 이모지로 항목이나 제목을 꾸미지 않는다 (✅ 📌 🚀).
- 문단으로 쓸 내용을 불릿으로 쪼개지 않는다. 불릿은 실제로 나열할 때만 쓴다.
- "**제목**: 설명" 형태의 불릿을 남발하지 않는다.
- 줄표(—)는 쓰지 않는다. 쉼표나 괄호를 쓰거나 문장을 나눈다.
- 쉼표를 과하게 쓰지 않는다. "~했더니, ~했고, ~하고 나니," 같은 문장은 둘로 나눈다.

## 7. 실험 보고서에서

- 실제로 관찰한 값을 쓴다. 콜로니 수, Ct 값, 농도, 시간, 실패하거나 예상과 달랐던 결과 등이다.
- 실험 중 실수나 이상한 점이 있었으면 그대로 쓰고, 원인을 추정한다. 매끄럽게 덮지 않는다.
- 수업에서 배운 개념과 연결한다. 교과서 일반론을 늘어놓지 않는다.
- 고찰과 결론에는 이 실험 결과로만 할 수 있는 말을 쓴다. "본 실험은 ~의 이해에 기여하였다는 점에서 의의가 있다" 같은 범용 결론은 쓰지 않는다.
- 참고문헌은 실제로 확인한 것만 쓴다. DOI, 페이지, 서지 정보가 맞는지 확인한다.

## 8. 과하게 고치지 않는다

위키백과 가이드는 아래 항목이 AI 판별 근거가 되지 못한다고 명시한다. 일부러 피하다 보면 오히려 어색해진다.

- 완벽한 문법, 격식체, 학술적 문체는 문제가 아니다.
- "또한", "따라서" 같은 접속사는 적당히 쓰면 괜찮다.
- 반복을 피하려고 같은 대상을 계속 다른 말로 바꾸지 않는다. 동의어를 돌려 쓰는 것 자체가 AI 신호다. 과학 글에서는 같은 개념을 같은 용어로 일관되게 쓴다.
- 줄표를 없앤 대신 쉼표와 짧은 문장만 늘어놓는 것도 그 자체로 신호다.
- 일부러 오타를 내거나 말투를 망가뜨리지 않는다.

## 9. 마무리 점검

1. 검색으로 확인한다: `단순`, `이는`, `이러한`, `통해`, `중요`, `시사`, `다양한`, `결론적으로`, `—`, `**`. 한 글에 많이 나오면 다시 쓴다.
2. 각 문단에 이 글에만 있는 구체적인 정보(수치, 관찰, 사례)가 하나 이상 있는지 본다.
3. 마지막 문단이 다른 보고서에 그대로 붙여도 말이 되면 다시 쓴다.
4. 소리 내어 읽어 보고, 주어나 대상이 불분명한 문장과 같은 단어가 반복되는 곳을 고친다.
5. 원문과 대조해 수치, 단위, 고유명사가 바뀌지 않았는지 확인한다.
