1. **`~/quiz_system_project/pharmacy/CLAUDE.md`, `docs/QUIZ_PLANNING_METHOD.md`,
   관련 과목 계획서 `docs/<과목>_*_PLAN.md` 를 먼저 읽는다.** 그림은 기존 덱의 방식도 확인한다.
2. 재료 정하기
   - 대시보드 🧩 로 복사한 요청(`/quiz <과목> <제목> … 연결된 자료: - 경로`)이면 **그 파일들이 주재료**다.
   - 키만 있으면 `bin/pa links <키>`. 연결이 없으면 과목 대응표로 `~/study_system/materials/<과목>/` (`요약/` 포함)와
     `~/study_system/notes/<과목>/` (사용자의 말 — 사용자가 기억하고 싶은 것) 에서 찾는다.
   - 무엇을 재료로 쓸지 목록을 보여 주고 확인받는다.
3. 그 프로젝트의 순서(자료 확인 → 계획서 → **사용자 승인** → 단계별 제작)와 브랜치·커밋 규칙을 따른다.
   승인 전에 덱 파일을 만들지 않는다. 덱 형식은 그 프로젝트 문서를 따른다.
4. 우선순위: `TODAY.md` 의 📝 시험(시험 모드), 3일 안 마감, 사용자가 말한 범위.
5. 덱이 앱에 들어가면 비서의 퀴즈 복습(틀린 문제 간격 반복)이 그 덱도 챙긴다 —
   사용자가 퀴즈 앱에서 [기록 내보내기]를 하면 된다고 알려 준다.
6. 퀴즈 앱 코드는 요청이 있을 때만 고친다 (그 프로젝트 규칙: 한 번에 한 단계, 고치기 전에 설명).
