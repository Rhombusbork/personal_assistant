## 0. 지금 상태 진단 (계획 수립 당시)

지금 시스템은 두 층으로 되어 있다.

| 층 | 무엇 | Claude 필요? |
|---|---|---|
| **코드 층** (`pa/*.py`, 약 720줄) | Canvas 수집, 제출 여부 확인, 제외·완료 기록, 학습 계획 배치, Google Calendar 동기화 | ❌ 이미 Claude 없이 동작 |
| **지시문 층** (`CLAUDE.md`, `.claude/skills/*`) | "오늘 뭐 해?" → 어떤 명령을 실행할지 Claude 가 판단 | ✅ 매번 토큰 사용 |

문제는 **입구가 Claude 채팅 하나뿐**이라는 점이다. 계산은 코드가 하는데도
"강의 들었어" 한마디를 처리하려고 Claude 가 지시문을 읽고, 명령을 고르고, 결과를 다시 설명한다.
→ **입력·기록·보기를 위한 입구를 코드로 따로 만들면** 일상 관리에서 Claude 호출이 거의 사라진다.

### 토큰이 드는 지점 vs 코드로 바꿀 수 있는 지점

| 일 | 지금 | 바꾼 뒤 |
|---|---|---|
| 할 일 추가 | Claude 가 문장 해석 → 명령 실행 | 입력 블록(파일 한 줄 / 입력창)이 바로 저장 |
| 완료·제외 표시 | Claude 대화 | 체크박스 클릭 / 버튼 |
| 계획 다시 짜기 | Claude 가 `pa.plan` 실행 | 입력이 바뀌면 자동 실행 |
| Canvas 새 과제 확인 | Claude 에게 물어봐야 함 | 정해진 시각에 자동 실행 |
| 오늘 할 일 보기 | Claude 가 요약 | 자동 생성된 화면을 VSCode 에서 열기 |
| 공지 해석, 자료 요약, 보고서 초안 | Claude | **그대로 Claude** (언어 작업) |

## 1. 전체 구조

```
┌──────────────── 입력 블록 ────────────────┐
│ inbox.md 체크리스트 │ VSCode 입력창/버튼 │ (선택) 자연어 → Claude │
└───────────────┬──────────────────────────┘
                ▼
┌──────────────── 코어 (Python, pa/) ──────────────────────────┐
│ 수집기: Canvas · Google Calendar · 시간표 · inbox             │
│ 저장소: 할 일 / 기록(event log) / 설정                         │
│ 계획기: 마감순 배치 (월수금토 → 일)                              │
│ 기록기: 완료·변경·소요시간 자동 기록                              │
└───────────────┬──────────────────────────────────────────────┘
                ▼
┌──────────────── 출력 블록 ────────────────┐
│ Google Calendar │ TODAY.md │ 대시보드(HTML) │ VSCode 사이드바 │
└──────────────────────────────────────────┘
                ▲
       자동 실행 블록 (폴더 열 때 / 정해진 시각 / 파일 저장 시)
```

원칙
- **코어는 하나**, 입력·출력은 갈아 끼울 수 있게 만든다. 아래 선택지들은 서로 섞어 쓸 수 있다.
- 모든 입구는 같은 명령(`pa ...`)을 부른다. Claude 도 같은 명령을 쓰므로 결과가 항상 같다.

## 2. 입력 블록 — 선택지

### 2-A. `inbox.md` 체크리스트 파일 ⭐ 추천 (1순위)

VSCode 에서 마크다운 파일 하나를 열어 두고 적기만 하면 된다. 저장하면 코어가 읽는다.

```markdown
## 할 일
- [ ] 리바이어던 발표자료 제출 @11-20 ~2h
- [ ] 린스타트업 발표자료 제출 @11-13 18:00 ~2h #창업
- [x] 린스타트업 텍스트 제출 @11-11          ← 체크하면 완료 기록
- [ ] 생화학 공부 ~1h every:tue,thu          ← 매주 반복
- [ ] 논문 읽기                              ← 기한 없음 = 장기 할 일

## 제외
- 생약학 조별학습활동 보고서                    ← Canvas 과제 이름 일부, 계속 무시
```

| 문법 | 뜻 |
|---|---|
| `@11-20`, `@11-20 18:00` | 마감 (시각 없으면 23:59) |
| `~2h`, `~40m` | 예상 소요 시간 |
| `#과목` | 과목·분류 |
| `every:tue,thu` | 매주 반복 |
| `[x]` | 완료 |

- 장점: 별도 프로그램 없음, 가장 빨리 입력, git 으로 이력 보관, 휴대폰에서도 (GitHub 앱 등) 편집 가능
- 단점: 문법을 조금 익혀야 함 → 잘못 쓴 줄은 TODAY.md 상단에 "해석 실패" 로 표시
- 규모: 파서 + 테스트 약 150줄

### 2-B. VSCode 작업(Tasks) 입력창 + 버튼

`Ctrl+Shift+P → 작업 실행 → "할 일 추가"` 를 누르면 입력창이 차례로 뜬다 (제목 → 마감 → 시간).
상태 표시줄 버튼 확장(예: *Task Buttons*)을 쓰면 아래쪽에 `➕ 할 일` `🔄 동기화` `📅 오늘` 버튼이 생긴다.

- 장점: 문법을 몰라도 됨, 코드 거의 없음 (`.vscode/tasks.json` 설정만)
- 단점: 여러 개를 한 번에 넣기 불편, 완료 체크는 따로 해야 함
- 규모: 설정 파일만

### 2-C. 대시보드 안의 입력 폼 (5-C 와 함께)

대시보드 페이지에 입력칸·체크박스를 넣고, 누르면 로컬 서버가 저장한다.

- 장점: 보면서 바로 고침, 가장 "앱" 같음
- 단점: 로컬 서버가 켜져 있어야 함
- 규모: 서버 + 페이지 약 300줄

### 2-D. 자연어 입력 (Claude 를 보조로만)

`pa add "다음주 금요일까지 리바이어던 발표자료 2시간"` 처럼 쓰면
① 먼저 **규칙 기반 파서**(날짜·시간 표현 정규식)가 시도하고
② 실패할 때만 `claude -p` 로 해석한다. → 대부분 토큰 0, 가끔만 사용.

## 3. 저장소 (데이터) — 선택지

| 선택지 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **3-A. JSON 유지** (지금) | `data/state.json` | 단순 | 기록이 쌓이면 느리고 통계 어려움 |
| **3-B. SQLite** ⭐ 추천 | `data/pa.db` 한 파일, 표: `tasks`, `events`, `sessions` | 통계·그래프·3단계 컨디션 데이터와 연결 쉬움, 파이썬 기본 내장 | 파일을 눈으로 직접 보긴 어려움 |
| **3-C. 마크다운이 원본** | `inbox.md` 가 곧 데이터베이스 | 투명함 | Canvas 항목·기록까지 담기엔 한계 |

추천 조합: **입력 원본은 `inbox.md`, 내부 저장은 SQLite.**
inbox 를 읽을 때마다 SQLite 와 맞추고, Canvas 항목·기록·통계는 SQLite 에만 둔다.

## 4. 자동 기록 블록 — 무엇을, 언제

### 4-1. 기록할 것 (event log)

| 기록 | 언제 생기나 | 쓰임 |
|---|---|---|
| `task_added` | inbox 에 새 줄 / Canvas 에 새 과제 | "새로 생긴 일" 알림 |
| `task_done` | inbox 체크 / Canvas 제출 감지 / 강의 완료 | 진도, 완료율 |
| `task_ignored` | 제외 목록 | 다시 안 보이게 |
| `due_changed` | Canvas 마감 변경 감지 | "마감이 바뀌었어요" 표시 |
| `plan_made` | 계획 재생성 | 계획 vs 실제 비교 |
| `session` (선택) | 집중 타이머 시작·종료 | 실제 소요 시간 → 예상 시간 자동 보정 |

- **예상 시간 자동 보정**: 같은 종류(예: 생약학 강의)의 실제 시간이 쌓이면 다음 계획부터 평균값을 쓴다.
- 이 기록이 그대로 **3단계(컨디션·스트레스)의 재료**가 된다 (몰린 날, 밀린 일 수 등).

### 4-2. 자동 실행 방식 — 선택지 (섞어 쓸 수 있음)

| 선택지 | 동작 | 장점 | 단점 |
|---|---|---|---|
| **4-A. VSCode 폴더 열 때** ⭐ | 작업 공간을 열면 동기화+계획 1회 | 설정만으로 됨 | VSCode 를 안 열면 안 돎 |
| **4-B. 파일 저장 감시** ⭐ | VSCode 가 켜진 동안 `inbox.md` 저장 → 즉시 재계획 | 입력 즉시 반영 | VSCode 켜져 있을 때만 |
| **4-C. WSL 타이머 (systemd)** | 매일 07:00, 18:00 Canvas 확인·재계획 | VSCode 없이도 돎 (이 PC 는 systemd 켜져 있음) | PC/WSL 이 켜져 있어야 함 |
| **4-D. Windows 작업 스케줄러** | 로그인 시·정해진 시각에 `wsl.exe` 로 실행 | WSL 이 꺼져 있어도 깨워서 실행 | 설정이 조금 번거로움 |

추천: **4-A + 4-B 로 시작**, 익숙해지면 4-C 추가.

## 5. 시각화 블록 (VSCode 안에서 보기) — 선택지

### 5-A. 자동 생성 `TODAY.md` ⭐ 가장 먼저

코드가 매번 덮어쓰는 읽기 전용 마크다운. VSCode 미리보기(`Ctrl+Shift+V`)로 옆에 띄워 둔다.

```markdown
# 11/11(수) · 남은 일 12 · 오늘 4h/4h
## 📅 오늘
| 시간 | 할 일 | 마감 |
| 14:55–15:55 | 린스타트업 텍스트 제출 | **오늘 23:59** 🔴 |
## ⏰ 3일 안 마감 …
## 📊 과목별 진도  생약학Ⅰ ████████░░ 80% …
## ⚠️ 해석 실패한 inbox 줄 …
```
- 장점: 추가 설치 없음, 가장 가벼움 / 단점: 그래프 표현 한계 (텍스트 막대 정도)
- 확장: *Markdown Preview Mermaid Support* 확장을 깔면 **간트 차트**도 그릴 수 있음

### 5-B. 정적 HTML 대시보드 + Live Server ⭐ 추천 (본격 시각화)

코드가 `dashboard/index.html` 과 `data.json` 을 생성 → 이미 설치된 **Live Server** 나
VSCode 내장 *Simple Browser* 로 VSCode 탭 안에서 연다. 데이터가 바뀌면 자동 새로고침.

화면 구성 후보
1. **D-day 타임라인**: 앞으로 14일 마감을 가로 띠로
2. **주간 계획 보드**: 요일 × 시간 칸에 학습 블록 (수업·약속은 회색)
3. **과목별 진도 막대**: 강의 들은 수 / 전체
4. **부하 그래프**: 날짜별 계획 시간 + 하루 한도선 → 몰리는 날 미리 보기
5. **완료 추이**: 주별 완료 개수, 예상 vs 실제 시간
6. (3단계) 컨디션·스트레스 곡선

- 장점: 그래프 자유로움, 휴대폰으로도 같은 페이지를 볼 수 있게 확장 가능
- 단점: 보기 전용 (입력은 inbox 로) / 규모: 생성기 + 페이지 약 400줄

### 5-C. 로컬 웹앱 (보기 + 입력)

5-B 에 작은 파이썬 서버(표준 라이브러리 또는 FastAPI)를 붙여, 페이지에서 체크·추가·제외까지.
- 장점: 한 화면에서 전부 / 단점: 서버 관리, 규모 약 700줄

### 5-D. VSCode 확장 (사이드바 패널)

왼쪽 탐색기 옆에 **"오늘 할 일" 트리**가 생기고, 항목 옆 체크·제외 버튼, 클릭하면 강의 열기.
아래 상태 표시줄에 `다음: 생약학 강의 15:00 · 마감 2건` 표시.
- 장점: VSCode 와 가장 자연스럽게 합쳐짐 / 단점: TypeScript 로 별도 개발, 규모가 가장 큼 (1,000줄+)
- 현실적 순서: 5-A/5-B 로 충분히 써 본 뒤 필요하면

### 비교

| | 설치 | 개발량 | 그래프 | 입력 겸용 | VSCode 일체감 |
|---|---|---|---|---|---|
| 5-A TODAY.md | 없음 | 작음 | △ | ✗ | ○ |
| 5-B HTML 대시보드 | Live Server(있음) | 중간 | ◎ | ✗ | ○ |

## 6. Claude 의 남는 역할 (토큰을 쓰는 곳만)

| 일 | 방식 |

## 8. 정해야 할 것 (선택 체크리스트)

1. **입력 방식**: ☐ 2-A inbox.md ☐ 2-B VSCode 입력창/버튼 ☐ 2-C 대시보드 폼 ☐ 2-D 자연어 (복수 선택 가능)
2. **저장소**: ☐ 3-A JSON 유지 ☐ 3-B SQLite ☐ 3-C 마크다운 원본

## 9. Windows 작업 스케줄러로 발전 (계획)

### 왜 필요한가
지금 감시기는 **VSCode 를 열어 둔 동안만** 돈다. VSCode 를 안 연 날에는 Canvas 새 과제가 계획·휴대폰 캘린더에 반영되지 않는다.

### 왜 WSL 의 systemd 타이머가 아니라 Windows 작업 스케줄러인가
이 PC 의 WSL 은 systemd 가 켜져 있지만, **WSL 은 열린 창이 없으면 몇 분 뒤 꺼진다.** 꺼진 WSL 안의 타이머는 돌지 않는다.
Windows 작업 스케줄러는 `wsl.exe` 를 불러 **WSL 을 깨워서** 실행할 수 있다.

### 설계
| 항목 | 값 |
|---|---|
| 실행 내용 | `wsl.exe -d Ubuntu -u neojun6007 -- /home/neojun6007/personal_assistant/bin/pa run --full` (이미 있는 명령) |
| 언제 | ① 로그인할 때 ② 매일 07:00 · 13:00 · 19:00 |
| 놓친 경우 | "예약된 시작 시간을 놓친 경우 가능한 빨리 실행" 켜기 (노트북이 꺼져 있었을 때) |
| 제한 | 10분 넘게 걸리면 중지 / 사용자가 로그온한 경우에만 실행 (WSL 은 사용자 세션 필요) |
| 겹침 방지 | ✅ 이미 구현: `run()` 이 `data/run.lock` 으로 한 번에 하나만 실행 → 감시기와 동시에 돌아도 캘린더 중복 없음 |

### 남은 작업 (단계)
1. **S1 기록 파일**: 창 없이 돌 때를 위해 실행 결과를 `data/pa.log` 에 남기고, 실패하면 TODAY.md·대시보드 "확인 필요"에 표시
2. **S2 등록 스크립트**: `scripts/windows/register-task.ps1` — PowerShell `Register-ScheduledTask` 로 위 설정을 한 번에 등록 (사용자가 한 번 실행)
3. **S3 시험**: 작업 스케줄러에서 "지금 실행" → `data/pa.log` 와 캘린더 확인
4. **S4 정리**: 스케줄러가 켜지면 감시기의 3시간 Canvas 확인은 끄고 (`CANVAS_EVERY`), 감시기는 inbox 저장 반영만 담당

### 선택지
- 실행 시각: 하루 3회 (추천) / 매 2시간 / 로그인할 때만
- 실패 알림: TODAY.md 표시만 (추천) / Windows 알림(토스트)까지 — 토스트는 PowerShell `BurntToast` 모듈 필요

## 10. GitHub Pages 로 확장 (계획)

### 목표
같은 대시보드를 **휴대폰에서도** 본다. (대시보드는 이미 휴대폰 폭 390px 에서 가로 넘침 없이 표시되는 것을 확인함)

### 가장 큰 문제: 공개 범위
GitHub Pages 사이트는 **누구나 주소만 알면 볼 수 있다** (비공개 저장소라도 사이트는 공개 — 기업용 요금제 제외).
대시보드 데이터에는 수업 시간표, 과목명, 할 일 제목, 약속 이름이 들어 있다. → 그대로 올리면 안 된다.

### 선택지
| | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A ⭐** | **데이터 암호화 후 공개 Pages** — 올릴 때 `data.js` 를 AES-GCM 으로 암호화(`data.enc.js`), 페이지에서 비밀번호 입력 시 브라우저가 복호화(WebCrypto, 라이브러리 없음). 비밀번호는 휴대폰에 한 번 저장 | 무료, 지금 구조 그대로, 퀴즈 앱과 같은 GitHub Pages 경험 | 비밀번호를 잊으면 다시 설정 / 페이지 틀(코드)은 공개 |
| B | 민감 정보를 지운 데이터만 공개 (제목 → "과제 1" 등) | 단순 | 쓸모가 크게 줄어듦 |
| C | Pages 대신 claude.ai 아티팩트(비공개 페이지)에 올림 | 로그인한 본인만 봄 | 갱신할 때 Claude 를 거쳐야 함 → "Claude 없이" 목표와 어긋남 |
| D | Cloudflare Pages + Access (이메일 로그인) | 진짜 로그인 보호 | 새 서비스 가입·설정 필요 |

### 설계 (A 기준)
1. **별도 저장소** `pa-dashboard` (공개) — 비서 저장소와 분리, 코드에는 개인 정보 없음
2. `bin/pa publish`:
   - `dashboard/index.html` + 복호화 코드 + `data.enc.js` 를 묶어
   - `gh-pages` 브랜치에 **이력 없이 한 커밋으로 강제 push** (과거 데이터가 git 이력에 쌓이지 않게)
   - 비밀번호는 `.env` 의 `DASHBOARD_PASSWORD` (git 제외)
3. 언제 올리나: `run --full` 이 끝날 때 (하루 몇 번) — inbox 저장마다 올리면 커밋이 너무 많음
4. 휴대폰: 주소를 홈 화면에 추가 → 앱처럼 사용

### 남은 작업 (단계)
1. **G1** 암호화/복호화 (Python 쪽 암호화 + 페이지 WebCrypto 복호화, 같은 형식인지 테스트)
2. **G2** `bin/pa publish` + `pa-dashboard` 저장소 생성 (GitHub, `gh` 사용)
3. **G3** Pages 켜기, 휴대폰에서 비밀번호로 열리는지 확인
4. **G4** `run --full` 뒤 자동 publish 연결 (9장 스케줄러와 합치면 VSCode 없이도 휴대폰 화면 갱신)

### 정해야 할 것
- 선택지 A/B/C/D 중 무엇으로 할지
- 대시보드에 휴대폰용 입력(체크·추가)까지 원하는지 — 원하면 정적 Pages 로는 안 되고 서버나 GitHub API 를 써야 해서 설계가 커짐
