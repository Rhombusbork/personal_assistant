# 개인 최적화 비서 — 종합 설계서

> 작성 2026-11-12 · 상태: **R1~R8·R10 구현 완료 (2026-11-12)**, R9 컨디션 보류, R11 퀴즈 연결 완료, Pages 남음
> 이 문서는 지금까지의 대화, 다른 비서 프로그램 조사, 사용자의 말에서 읽은 욕구를 바탕으로 한 전체 설계다.
> 이미 만든 것은 ✅, 이번에 설계하는 것은 🆕, 사용자가 말하지 않았지만 제안하는 것은 💡 로 표시한다.

**목표 한 줄:** *"내가 해야 할 일을 기억하고, 언제 할지 정해 주고, 시작을 쉽게 해 주고, 할 수 있는 건 대신 준비해 주는 — 가볍고 한 창에서 다 되는 비서"*

## 1. 지금까지 사용자가 말한 것 (정리)

### 1-1. 큰 목표 (처음 말한 그대로)
1. **일정/할 일 관리**
2. **에이전틱 자동화된 할 일 수행**
3. **컨디션/ 스트레스 관리**

### 1-2. 관리 대상
| 분류 | 사용자의 말 |
|---|---|
| 정기적으로 해야 하는 것 | 과제 및 온라인수업 듣기 |
| 추가하면 기억해 줘야 하는 것 | 일정들 (약속, 회의 등) |
| 기록해 줘야 하는 것 | 수업시간 |
| 그 외 하고 싶은 일들 | 장기적인 todo 로서 기록 / "기한은 정해지진 않았는데 내가 하고자 하는 일" |

### 1-3. 요구 사항 (대화 순서대로)
| # | 요구 | 상태 |
|---|---|---|
| 1 | 현실의 일정(Google Calendar)과 연결 | ✅ |
| 2 | 학교 LMS(제주대 Canvas) 연동 | ✅ 과제·퀴즈·강의 목록·제출 여부 |
| 3 | 알림은 안 줘도 됨 | ✅ (알림 없음) |

## 2. 사용자의 말에서 읽은 욕구

말 그 자체보다 **왜 그렇게 말했는지**를 추정했다. 틀린 부분은 고쳐 주면 설계에 반영한다.

| 사용자의 말 | 읽은 욕구 | 설계에 반영 |
|---|---|---|
| "**개인 최적화** 비서" | 남들 기준이 아니라 **나에게 맞춰지는** 도구. 쓸수록 나를 알아 가는 것 | 실제 소요 시간 학습, 내 리듬(요일·시간대) 학습 (5-B) |
| "에이전틱 자동화된 할 일 수행", "프로그램이 수행 가능한 작업을 **에이전트로서 최대한**" | 해야 할 일의 **양을 실제로 줄이고 싶다**. 기억·관리만이 아니라 *준비 작업 자체*를 맡기고 싶다 | 에이전트 작업 목록 (6장), 보고서 준비+초안 |
| "**같은 과제를 계속 신경 안 쓰게**" | 머릿속에서 **잊어도 되는 상태**(인지 부담 덜기). 한 번 판단한 건 다시 판단하고 싶지 않음 | 제외는 영구, 제출은 자동 감지, 공지 기반 제외 제안 |
| "강의 **여는 작업까지**", "자료 열기", "왼쪽 바로 누르면 되니까" | **시작하는 마찰**을 없애고 싶다. 클릭 수가 적을수록 좋다 | "지금 할 일" 카드에 [▶ 열기] 하나, 자료 자동 매칭 |
| "월수금토… **안 되면 일요일**" | 화·목·일은 **쉬거나 다른 일**에 쓰고 싶다. 일요일은 최후의 수단 → **휴식 보호** 욕구 | 쉬는 요일 보호, 하루 상한, 몰림 경고 (5-C) |
| "마감일이 **가장 조금 남은** 것부터" | **마감을 놓치는 불안**을 없애고 싶다 | D-day 강조, 여유 시간 지표 💡 |
| "**시각화**되어 표현", "오늘 목요일인데?" | **한눈에 통제감**을 느끼고 싶다. 보이는 정보가 **정확해야 믿는다** | 실시간 시계, "엔진 상태" 표시, 갱신 시각 노출 |
| "**토큰을 덜**", "**무겁지 않게**" | **비용·자원 의식**, 단순하고 오래 쓸 수 있는 구조 선호 | 코드 우선, Claude 는 버튼으로만, 라이브러리 없음 |
| "**선택지 여러 개**", "**확정짓지는 말아봐**", "**논의**하고 싶어" | **주도권은 내가** 갖고 싶다. 자동화돼도 결정은 내가 | 에이전트는 *제안·준비*까지, 확정은 사용자. 설정 노출 |
| "이해하지 못했어", "감시기가 뭐지?" | 기술 설명은 **쉬운 말로**. 내부 작동을 알고 싶어 함 | 용어 정리 (부록), 화면에 상태를 말로 표시 |
| study_system "**내 말로** 기록", report "사람다운 글쓰기" | **진짜로 배우고**, **내 목소리**로 쓰고 싶다 | 초안에 `[✍ 내 생각]` 자리, 노트는 내 말 그대로 |
| quiz 시스템을 직접 만들어 둠 | **시험 대비를 체계화**하고 싶다. 기억에 남기는 공부 | 시험 모드·간격 반복 연결 💡 (5-E) |
| 3단계 "컨디션/스트레스" | 일만 잘하는 게 아니라 **지치지 않고** 하고 싶다 | 아침·저녁 30초 점검으로 데이터부터 쌓기 💡 |

**한 문장으로:** 사용자는 *"놓치지 않을까 하는 걱정과 시작하는 귀찮음을 비서에게 넘기고, 남은 에너지로 진짜 공부와 하고 싶은 일을 하되, 결정권은 내가 갖고, 지치지 않게"* 를 원한다고 읽었다.

### 연구에서 가져온 원칙
- **계획 오류(planning fallacy):** 사람은 걸리는 시간을 체계적으로 짧게 잡는다. 졸업논문 연구에서 예상 33.9일 → 실제 55.5일 [10]. 경고만으로는 잘 안 고쳐진다 → **실제로 걸린 시간을 재서 다음 예상을 자동 보정**하는 것이 현실적 해법
- **실행 의도(if-then 계획):** "언제·어디서·무엇을" 정해 두면 목표 달성이 뚜렷하게 늘어난다 (메타분석 d≈0.65) [11] → 계획 블록에 **시간 + (선택) 장소**를 붙이고, "지금 할 일" 카드로 시작 신호를 준다

## 4. 설계 원칙

1. **결정은 사용자, 준비는 비서** — 에이전트는 초안·제안·준비까지. 제출·확정은 사람이 한다
2. **한 번 판단한 것은 다시 묻지 않는다** — 제외·완료·설정은 기억된다
3. **시작 버튼 하나** — 해야 할 일 옆에 그 일을 시작하는 버튼(열기·자료·작성)이 있다
4. **보이는 정보는 정확해야 한다** — 갱신 시각·엔진 상태를 항상 표시, 틀리면 경고
5. **코드 먼저, Claude 는 버튼으로** — 반복되는 일은 코드, 언어가 필요한 일만 Claude
6. **가볍게** — 파이썬 기본 기능 + 라이브러리 없는 HTML. 새 서비스 가입 최소화
7. **쉬는 시간도 일정이다** — 휴식·쉬는 요일을 지키는 것이 계획의 일부
8. **쉬운 말** — 화면 문구와 설명은 기술 용어 없이

## 5. 기능 설계

### 5-A. 수집 (무엇을 해야 하는지 알기)
| 기능 | 상태 | 설명 |
|---|---|---|
| Canvas 과제·퀴즈·마감 | ✅ | 3시간마다. 제출하면 자동 완료 (조장 대표 제출 포함) |
| Canvas 온라인 강의 (이번 주·다음 주) | ✅ | 출석 마감은 주차 이름의 날짜로 계산 |

| 직접 입력 (대시보드·inbox.md) | ✅ | 날짜·몇 시까지·예상 시간·분류·반복 |

| **큰 일 쪼개기** | 💡 | 보고서·발표처럼 2시간 넘는 일은 단계로 나눠 **마감 며칠 전부터 나눠 배치** (한 번에 몰지 않음) |
| **반복 습관 유연 배치** | 💡 | "생화학 공부 주 3회 1시간" → 정해진 요일이 아니라 그 주 빈 시간에 알아서 3번 (Reclaim 방식) |
| **여유 시간 지표** | 💡 | 남은 일 총시간 vs 마감 전 쓸 수 있는 시간 → "이번 주 여유 +5h" / "부족 -2h, 무엇을 뺄까요?" (Shovel 방식) |
| **쉬는 시간 보호** | 💡 | 저녁 몇 시 이후·특정 요일은 배치 금지, 블록 사이 휴식 (지금 10분 → 설정 가능) |
| **이유 표시** | 💡 | 블록을 누르면 "왜 여기?" — "마감 11/16 이라 월수금토 중 가장 빠른 빈 시간" |

### 5-C. 화면 (대시보드) — `dashboard-design.md` 초안을 확장
| 기능 | 상태 | 설명 |
|---|---|---|
| [오늘] 타임라인 / [이번 주] 캘린더 전환 | 🆕 | 마지막 보기 기억 |
| **[학기] 지도** | 💡 | 종강까지 주 단위 막대: 마감·시험 몰리는 주를 미리 봄 |
| "지금 할 일" 카드 + 시작 버튼 | 🆕 | ▶ 강의 열기 / 📄 자료 / ✍ 보고서 / ✓ |
| 오른쪽: 마감 · 하고 싶은 일 · 🤖 작업 | ✅/🆕 | |
| 엔진 상태 · 갱신 시각 | ✅ | "실시간 / 보기 전용" |
| **아침 점검 (30초)** | 💡 | 처음 열 때: 오늘 할 일 확인 → 컨디션 1~5 → [시작] |

| 키보드 단축키 | 💡 | Ctrl+K 입력, `t` 오늘, `w` 주간, `space` 지금 할 일 완료 |

### 5-D. 에이전트 (대신 해 주기) — 6장 표 참고

모든 작업은 **🤖 작업 칸**에 진행 상황과 결과가 남는다.

### 5-E. 학습 연결 (study_system · quiz)
| 기능 | 상태 | 설명 |
|---|---|---|

| **시험 모드** | 💡 | 시험일 입력 → 시험 전 주들에 복습 블록 자동 배치, 관련 퀴즈 덱 연결 |

### 5-F. 컨디션·스트레스 (3단계)
조사한 Bearable 처럼 **기록 → 관계 발견** 순서로 간다. 처음부터 웨어러블 연동은 하지 않는다.
| 단계 | 내용 |
|---|---|
| F1 기록 | 아침 컨디션 1~5, 저녁 기분·스트레스 1~5, 잠든·일어난 시각(선택) — 각 10초 |
| F2 자동 지표 | 이미 있는 데이터로 계산: 하루 계획 시간, 놓친 블록 수, 미룬 횟수, 마감 몰림, 쉬는 날 수 |
| F3 관계 보기 | "잠 6시간 미만인 날 완료율 -30%" 같은 상관을 그래프로 (인과 아님을 표시) |
| F4 계획에 반영 | 컨디션 낮은 날은 하루 상한을 자동으로 낮추고 쉬운 일부터 / 스트레스 높게 연속되면 "이번 주 뺄 수 있는 일" 제안 |

### 6-2. 조건부 ⚠️ (시험해 봐야 앎 / 대가가 있음)
| 작업 | 조건·이유 | 대안 |
|---|---|---|
| **강의 자료(배포용 PDF) 자동 다운로드** | 자료가 학교 강의 플랫폼(LearningX) 안에 있어 Canvas 토큰으로는 막힘(확인함). **로그인한 브라우저를 자동 조작**하는 방식이 필요: 처음 한 번 직접 로그인한 브라우저 프로필을 저장해 두고 그 프로필로 열어 받는 방식 [12]. 학교 로그인 방식(보안 인증)과 플랫폼이 다운로드를 허용하는지에 달림. 학교 이용 규정도 확인 필요 | 안 되면 "다운로드 필요" 표시 + [강의 열기] 로 직접 받기 → 받은 파일은 **다운로드 폴더를 지켜보다가 자동으로 과목 폴더로 옮김** (이건 확실히 가능) |
| **강의 수강 여부 자동 확인** | 진도도 LearningX 안. 위와 같은 브라우저 방식이면 읽을 수 있을 가능성 | 지금처럼 ✓ 들었음 버튼 |
| **강의 영상 내용 요약** | 영상 파일·자막을 받아야 함. 다운로드가 막혀 있을 가능성이 크고, 받는 것 자체가 학교 규정에 걸릴 수 있음 | **배포용 PDF 요약을 우선**. 영상은 들으면서 study_system 에 내 말로 기록 |
| 휴대폰에서 보기 | GitHub Pages 는 공개라 **암호화 필요** | 지금은 Google Calendar 앱 |
| 휴대폰에서 **입력** | 정적 페이지로는 불가. 서버나 GitHub API 필요 → 무거워짐 | Google Calendar 에 일정 추가 → 엔진이 읽어 반영 (약속은 이미 됨) |
| VSCode 를 닫아도 동작 | Windows 작업 스케줄러 연결 필요 (계획 있음) | 지금은 VSCode 를 열면 따라잡음 |
| Claude 백그라운드 작업 | **구독 사용량 한도를 채팅과 함께 씀**. 많이 돌리면 채팅이 막힐 수 있음 | 버튼으로만 호출, 작업 칸에 몇 번 썼는지 표시 💡 |
| 대시보드 자동 열기 | VSCode 설정(자동 작업 허용)이 필요하고, 제가 VSCode 화면을 직접 시험할 수 없음 | 작업 실행 메뉴 / 브라우저 주소 |
| 성적 알림 | Canvas 점수 API 가 학생에게 열려 있는지 확인 필요 | — |

### 6-3. 할 수 없음 / 하지 않음 ❌
| 요청·가능성 | 이유 |
|---|---|
| **강의를 대신 재생해 출석 채우기** | 출석·수강 기록을 거짓으로 남기는 일 — 학교 부정행위. (사용자도 "여는 작업까지"로 정정함) |
| **과제·퀴즈를 대신 제출하거나 퀴즈를 대신 풀기** | 같은 이유. 비서는 초안·준비까지, 제출은 사용자 |
| **초안을 그대로 내 작업으로 제출하게 만들기** | 초안은 출발점. 내 생각 자리를 비워 두는 이유. 과목마다 AI 사용 규정이 다르니 확인 필요 |
| 대시보드 버튼 → Claude 채팅창에 바로 말 넣기 | (사용자가 필요 없다고 함) Claude Code 확장이 그런 통로를 공식 제공하는지 확인 안 됨 |
| Canvas 새 과제의 **즉시**(푸시) 반영 | 학생 계정으로는 알림 연결(webhook)이 없음 → 정해진 간격으로 확인 (지금 3시간) |
| 강의 실제 길이 정확히 알기 | API 에 영상 길이가 없음 → 예상 시간(50분) + 실제 측정으로 보정 |
| Canvas 파일 메뉴로 자료 받기 | 학교가 학생 접근을 막음 (401 확인) |

## 7. 전체 구조 (기술)

```
                ┌────────────── 비서 엔진 (bin/pa watch, 파이썬) ───────────────┐
 Canvas API ───▶│ 수집기        계획기         기록기(events)    에이전트 작업 대기열 │
 Google Cal ◀──▶│ collect_*  →  plan  →  SQLite(data/pa.db)  ←  jobs: 보고서·자료·  │
 inbox.md   ◀──▶│ inbox                                              요약·다운로드  │
 materials/ ◀───│                     로컬 서버 :8765                  │ claude -p │
                └──────────────────────────┬──────────────────────────┴───────────┘
                                           ▼
                     대시보드 (VSCode 탭)  ·  TODAY.md  ·  (나중) 암호화 Pages
```

- **에이전트 작업 대기열** (🆕): 오래 걸리는 일은 대기열에 넣고 하나씩 처리. 상태는 DB 의 `jobs` 표 → 🤖 작업 칸
- **파일 열기**: 엔진이 VSCode 터미널 안에서 돌기 때문에 `code <파일>` 로 같은 창에 연다
- **Claude**: `claude -p` (읽기 위주 권한, 작업 폴더 제한). 보고서 초안처럼 쓰기가 필요한 일은 결과 텍스트를 엔진이 받아 파일로 저장 → Claude 에게 쓰기 권한을 주지 않음
- **가벼움 유지**: 새 라이브러리는 브라우저 자동화(Playwright)뿐이고, 그것도 자료 다운로드 단계에서만 (이미 퀴즈 프로젝트에 설치돼 있음)

## 8. 단계별 로드맵 (제안)

| 단계 | 내용 | 결과 | 규모 |
|---|---|---|---|
| ✅ **R1 화면 개편** | [오늘]/[이번 주] 전환, 지금 할 일 카드, 종류별 버튼, Ctrl+K, 통계 접기 | 매일 쓰기 편한 화면 | 중 |
| ✅ **R2 자료** | 자료 매칭·열기, **다운로드 폴더 → 과목 폴더 자동 정리** | 자료 찾는 시간 0 | 소 |
| ✅ **R3 보고서 에이전트** | 작업 대기열 + 보고서 준비·초안 + 🤖 작업 칸 | 버튼 하나로 초안 | 중 |
| ✅ **R4 아침·저녁 점검** (컨디션 제외) | 30초 점검, 못한 일 넘기기, 컨디션 기록 시작 (3단계 F1) | 하루 리듬 + 데이터 | 소 |
| ✅ **R5 계획 똑똑하게** | 실제 시간 측정·보정, 큰 일 쪼개기, 여유 시간 지표, 쉬는 시간 보호 | 계획이 현실과 맞음 | 중 |
| ✅ **R6 공지·시험** (학기 지도 제외) | 공지 요약 → 제외 제안, 시험 모드, 학기 지도 | 놓치는 것 없음 | 중 |
| ✅ **R7 자료 자동 다운로드** (성공) | 로그인 브라우저 방식으로 LearningX 배포용 PDF 받기 시험 → 되면 자동화, 안 되면 R2 방식 유지 | 조건부 | 중 |
| ✅ **R8 PDF 요약** | materials 의 새 PDF → 핵심 정리 파일 (버튼) | 공부 준비 | 소 |
| ⏸ **R9 컨디션 분석** (보류) | F2~F4 | 3단계 | 중 |
| ✅ **R10 VSCode 밖으로** (작업 스케줄러, Pages 는 계획만) | 작업 스케줄러, 암호화 Pages | 항상 최신, 휴대폰 보기 | 중 |
| ✅ R11 퀴즈 연결 (퀴즈 앱 수정 없이 '기록 내보내기' 파일로) | 퀴즈 결과 내보내기 → 복습 일정 | 시험 대비 | 중 (퀴즈 앱 수정 필요) |

추천 순서의 이유: **매일 쓰는 화면(R1) → 가장 자주 하는 귀찮은 일(R2 자료, R3 보고서) → 습관(R4) → 정확도(R5)** 순으로 체감이 크다.

## 9. 사용자가 정할 것

1. 2장의 욕구 분석이 맞는지 — 특히 "화·목·일은 쉬고 싶다"는 해석, "결정은 내가"라는 해석
2. 💡 제안 기능 중 **원하는 것 / 필요 없는 것** (특히 아침·저녁 점검, 집중 타이머, 시험 모드, 큰 일 쪼개기)
3. 로드맵 순서 (R1 부터 갈지, 다른 것부터)
4. 자료 자동 다운로드(R7)를 **시험해 볼지** — 학교 로그인 정보를 저장한 브라우저 프로필이 이 컴퓨터에 생긴다는 점 포함
5. 컨디션 기록을 **어디까지** (1~5 점수만 / 수면 시각까지 / 메모까지)
6. `dashboard-design.md` 의 열린 질문 5개 (버튼 표시 방식, 빈 시간에 넣기, 초안 분량, 색, 통계 위치)
